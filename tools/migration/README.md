# Retiring a Touch ID experiment

`touchid-transition.py` applies a separately reviewed, hash-pinned configuration plan and keeps an exact inverse. This is a standalone migration, not package setup. It never opens a sensor, writes SEP files, changes enrollment, restarts services, changes a boot default or uninstalls packages.

A plan names only PAM, systemd, modprobe and Mac-consent configuration. It records the old hash/mode/owner, the complete proposed new bytes, the required kernel release and the hashes of installed replacements. A live apply additionally requires an attended root terminal, `--live`, the matching running kernel/module and a passive ready report. The plan must pin `/sys/module/apple_sep/notes/.note.gnu.build-id`, not rely on a release name alone. New package files must already be installed and the new kernel booted before the authentication transition. Password login remains available until the attended test is completed. A preboot plan may preserve existing consent only for the two absent package-owned consent/options files, on the pinned working kernel with a restored, usable sensor and no guard refusals; it cannot change PAM or authorize a new enrollment.

Use `check`, `apply` or `rollback`, each with `--plan FILE --checkpoint DIRECTORY`. The checkpoint must be a new directory for apply. `--root PATH` is for an isolated test image and never implies a live transition. Apply validates every old file and new payload before changing anything; each atomic replacement is journalled and flushed. An error attempts the exact inverse. Rollback refuses to overwrite an administrator's intervening edits. If power is lost, run rollback with the same plan/checkpoint before attempting another transition. Keep the checkpoint private: it contains configuration, though it never contains fingerprint or enclave data.

The local plan removes experimental artifact gates after the replacement driver/provider are ready, preserves account restrictions, retains sudo's TTY condition with `pam_succeed_if`, and uses the separate parallel SDDM fingerprint service. It overrides the older support package's vendor drop-in by basename until that package is retired. Other distributions need their own reviewed PAM policy; this tool does not invent one.

After the positive/negative/password and lid checks pass, remove obsolete integration/support packages with the package manager, retaining their archives for rollback. Do not delete package-owned files by hand. Before retiring unowned release-specific loader units, verify their hashes and confirm that no remaining unit requires them. Keep old-kernel fallback loaders until the replacement cold boot is accepted. Publication and general M1 activation remain separate approvals and evidence boundaries.

Run `python3 -B tools/migration/test/transition-test.py`. The suite exercises real temporary-file transactions, each injected interruption, exact rollback, drift refusal, symlink handling, forbidden state paths and administrator changes. These are not PAM authentication or physical persistence results.
